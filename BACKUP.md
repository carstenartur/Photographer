# BACKUP.md — what to back up & what is recoverable from git

This document lists exactly what survives a complete loss of the local
working directory (i.e. what is reproducible from `git clone` alone),
what does **not** survive but can be regenerated locally, and what is
genuinely irreplaceable and therefore must live in a private backup
outside the public git repository.

> **Audience.** This is a recovery guide for the project owner. It
> assumes a fresh machine with `git clone` access to the public repo.

---

## TL;DR — minimum private off-repo backup

The public git repository is *self-sufficient* for everything except:

1. **Canon CCAPI / EDSDK reference PDFs** under `docs/` — copyrighted,
   not redistributable. Keep a private copy.
2. **C-RAW / dark / flat / as-is research fixtures** captured locally
   that are *too large* or *not yet useful enough* to commit. The two
   `g5xm2-detail-…-iq3-…-02.cr3` and `…-03.cr3` fixtures are already
   in git. The three older fixtures listed below are still untracked
   on the local machine — committing them is recommended (see
   §"Action: commit the missing CR3 fixtures").

Everything else — code, tests, ITs, Markdown notes, the production
decoder, the research harness — is in git already or covered by this
document's recommendations below.

## What is NOT in git and NOT reproducible — keep a private backup

### A. Canon SDK reference material (copyrighted)

Canon's developer documentation cannot be redistributed in a public
repository. Keep a private copy of the originals:

- `docs/CameraControlAPI_OperationGuide_EN.pdf` (≈ 0.7 MB)
- `docs/CameraControlAPI_Reference_v140_EN.pdf` (≈ 35 MB)
- `docs/ccapi_guide.txt` (text extract from the PDF above)
- `docs/ccapi_ref.txt` (text extract from the PDF above)
- Any other `EDSDK_*.pdf` you obtained directly from Canon

These are listed in `.gitignore`. Back them up to a **private** location
(personal cloud drive, encrypted USB, etc.) — never to the public repo.

### B. CR3 fixtures captured locally but not yet committed

The local working tree currently contains three `g5xm2-*.cr3` fixtures
that the research IT harness already references but that are **not yet
in git**:

| File | Size | Used by |
|---|---:|---|
| `canon-cr3-imageio/src/test/resources/samples/research/g5xm2-asis-iso200-ss130-ff2p5-01.cr3` | 18 MB | as-is panel; lossless RAW. |
| `canon-cr3-imageio/src/test/resources/samples/research/g5xm2-dark-iso125-ss160-ff7p1-20260504-192532-02.cr3` | 11 MB | `DarkFixtureLosslessDecoderIT`. |
| `canon-cr3-imageio/src/test/resources/samples/research/g5xm2-flat-iso1600-ss0p4s-ff1p6-20260504-193022-02.cr3` | 1 MB | `FlatFixtureLosslessDecoderIT`. |

These are *necessary* for the regression panel to detect the
predictor-seed production fix (README §"Update 2026-05-12 (p)"). They
are recapturable from a Canon G5X II in front of the same scene, but
that scene reproduction is approximate — committing the actual files
preserves the exact bitstream Round-13 was validated against.

→ **Action: commit them** (see §"Action" below). All three together
are 30 MB, well below GitHub's 50 MB / 100 MB soft / hard limits per
file; no Git LFS needed.

### C. Any `g5xm2-*.cr3` you capture in the future

Same rule: if a new fixture is going to be referenced by an IT, commit
it. The naming convention from
`samples/research/README.md#file-naming` keeps fixtures
self-documenting (`g5xm2-<phase>-iso<ISO>-ss<shutter>-f<aperture>-iq<imageQualityRaw>-<runId>-<seq>.cr3`).
Append the new row to `manifest.tsv` in the same commit.

### D. Generated debug images / overlays you found informative

If you produced an ad-hoc `target/cr3-decode-debug/<fixture>/plane-N.png`
that was the visual smoking gun for a bug, copy it into a dated subfolder
under `canon-cr3-imageio/src/test/resources/samples/research/visual-evidence/<YYYY-MM-DD>-<topic>/`
and commit it. Otherwise it is regenerable.

## Recovery procedure (after total local loss)

1. `git clone <repo-url> Photographer`
2. Restore the **private** Canon SDK PDFs into `docs/` from your private
   backup. (They are in `.gitignore` and will not be committed.)
3. (Optional) Connect the Canon G5X II over USB and re-capture any
   *additional* fixtures you used locally but that were not in git.
   Use the workflow in `samples/research/README.md` §"Capturing C-RAW".
4. Build: `mvn -B clean verify -pl common-api,app -am -Djava.awt.headless=true`
5. To regenerate the long Round-13 sweep (only if you actively want it):
   ```cmd
   mvn -B verify -pl canon-cr3-imageio -am ^
       -Dtest=NoSuchTestZZZ -Dsurefire.failIfNoSpecifiedTests=false ^
       -Dit.test=CrxPlaneFollowupRound13IT ^
       -Djunit.jupiter.conditions.deactivate=org.junit.jupiter.api.condition.DisabledCondition
   ```

- [ ] All local commits pushed to the public remote (`git status` clean,
      `git log @{u}..` empty).
- [ ] Private Canon SDK PDFs copied to private off-machine storage.
- [ ] Any new locally-captured CR3 fixture either committed or copied
      to private off-machine storage with the `manifest.tsv` row that
      describes it.
- [ ] `.gitignore` reviewed: any new tool-generated directory at the
      repo root added to it.
- [ ] `TODO.md` and `samples/research/README.md` reflect the current
      state of the CR3 import (running ledger).
