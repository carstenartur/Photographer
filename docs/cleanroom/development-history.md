## Early sources and remaining evidence

The April changes predate the formal source register. A recovered design discussion from 12 April 2026, 21:48 UTC, cited public LibRaw release notes and a forum discussion on CR3 cropping (SRC-015), along with the `lclevy/canon_cr3` container description. The discussion proposed using 64-bit offsets and bounds checks, separating metadata parsing and representing both sensor and visible image geometry. Earlier that day, a Java ImageIO implementation plan prepared for Copilot also cited the format description and the same forum thread. [LibRaw 0.22 release notes](https://www.libraw.org/news/libraw-0-22-0-release) · [CR3 crop discussion](https://www.libraw.org/node/2760) · [CR3 format description](https://github.com/lclevy/canon_cr3)

At 22:00 UTC, the architecture commit recorded those choices under “LibRaw Lessons Learned”. Its versions of [`BoundsCheck.java`](https://github.com/carstenartur/Photographer/blob/56fdcafa0bc6576759ef552d60e85cd418af14f3/canon-cr3-container/src/main/java/com/photographer/focusstack/cr3/bmff/BoundsCheck.java) and [`IsoBox.java`](https://github.com/carstenartur/Photographer/blob/56fdcafa0bc6576759ef552d60e85cd418af14f3/canon-cr3-container/src/main/java/com/photographer/focusstack/cr3/bmff/IsoBox.java) remain byte-identical in release 0.1.5. PR #41 and the historical [subband log](../../canon-cr3-core/SubbandFixtures.md) also cite the external container description. The surviving record identifies the cited format description. Its exact revision in PR #41 is unrecorded. The September 2026 revision is listed in the [reference register](source-register.json) as SRC-016.
