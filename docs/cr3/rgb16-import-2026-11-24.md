## Reproduce the RGB16 measurements

With the usual heap, `ImageIO.read(File)` measures the full-resolution RGB16 import. Repeat it under a constrained heap with a portrait file to exercise compact rotation. A third workload explicitly requests a smaller image through ImageIO source subsampling. [How the decoder handles both paths](decoder.md#compact-rgb16-orientation)

From each checkout, build the benchmark JAR with JDK 25. To run the public probe on Java 21, compile the same probe source with `javac --release 21` and place those classes first on the runtime classpath. The following Bash example uses the repository's G5 X Mark II RAW. Set `java_bin` to the Java 21 executable and `cpus` to four CPU IDs available on the Linux host. [Probe modes and recorded metrics](../../scripts/benchmarks/README.md#java-probe)

```bash
mvn -B -DskipTests -Pbenchmarks -pl canon-cr3-benchmark -am package
jar=canon-cr3-benchmark/target/benchmarks.jar
main=com.photographer.focusstack.cr3.benchmark.Cr3ImportProbe
src=canon-cr3-benchmark/src/main/java/com/photographer/focusstack/cr3/benchmark/Cr3ImportProbe.java
mkdir -p target/probe21
javac --release 21 -cp "$jar" -d target/probe21 "$src"
cpus=0-3
java_bin=java
sample=canon-cr3-imageio/src/test/resources/samples/sample.cr3

probe() {
    local heap=$1 gc=$2 file=$3
    shift 3
    taskset -c "$cpus" "$java_bin" -Xms24m "-Xmx$heap" "$gc" -XX:ActiveProcessorCount=4 \
        -cp "target/probe21:$jar" "$main" --input "$file" "$@"
}

probe 768m -XX:+UseSerialGC "$sample" --mode default --warmup 5 --iterations 5 --gc-between
probe 512m -XX:+UseSerialGC "$sample" --mode rgb16 --subsample-x 8 --subsample-y 8 \
    --warmup 4 --iterations 5 --gc-between
probe 144m -XX:+UseG1GC "$sample" --mode rgb16 --orientation 6 --memory-mode LOW_MEMORY \
    --warmup 2 --iterations 3 --gc-between
```

The last command forces the compact path through an explicit reader. To exercise automatic policy selection through `ImageIO.read(File)`, use `--mode default` on a file whose EXIF orientation is 6. For the repository G5 fixture, this creates the same portrait input by changing its existing CMT1 Orientation tag in a copy. The SHA-256 guard pins the tag offset to this recording. The RAW payload is identical.

```bash
python3 - "$sample" target/probe21/g5-orientation6.cr3 <<'PY_FIXTURE'
import hashlib, pathlib, sys
source, copy = map(pathlib.Path, sys.argv[1:])
data = bytearray(source.read_bytes())
assert hashlib.sha256(data).hexdigest() == "4d9f1d00d62d0c06a2448d6ea6d3f5820476c2d1a993eaa73a2352719f199a95"
data[410] = 6
copy.write_bytes(data)
PY_FIXTURE
probe 144m -XX:+UseG1GC target/probe21/g5-orientation6.cr3 --mode default \
    --warmup 2 --iterations 3 --gc-between
```

Keep stderr to confirm that AUTO selected compact processing. Run the same fixture, heap, GC, affinity and probe on each revision in at least three fresh JVMs per case. Alternate baseline/candidate order. Compare fork medians of import time and allocated bytes, and each fork’s peak RSS. A separate `--warmup 0 --iterations 1 --checksum` run hashes every returned channel. Check dimensions, band count, sample depth and the full hash across revisions. Report the spread when fork medians disagree on the direction of a timing change.

The earlier compact-mode study measured FAST and LOW_MEMORY with the original single-pixel permutation. The 2 × 3 subsampling study compared developing the full image and selecting sites afterwards with developing only the requested sites. The 8 × 8 comparison additionally exercises the smaller intermediate Bayer mosaic. ## TIFF metadata file reads

With OpenJDK 21, Java Flight Recorder counted `jdk.FileRead` events for one complete `ImageIO.read(File)` on each original. The baseline was `5018654ce97ca36d4596e8026a7386b10a4b9e7f`. The comparison changed the out-of-line TIFF `SHORT` array reader. Both versions returned the same three 16-bit bands, dimensions and full RGB16 fingerprints. The counts measure calls and bytes attributed to the input file. End-to-end latency requires a separate timing run. [Bulk TIFF array reads](decoder.md#cr3-metadata)

| Capture | File reads before | File reads after | Bytes read in each version | Full RGB16 FNV-1a |
| --- | ---: | ---: | ---: | --- |
| PowerShot G5 X Mark II RAW | 3,721 | 1,552 | 20,646,159 | `482d0cb8385a95c5` |
| PowerShot G5 X Mark II C-RAW | 3,712 | 1,543 | 9,655,321 | `5c286fbe36253461` |
| EOS R RAW | 5,511 | 2,013 | 36,123,708 | `ba1e15e786312378` |

Use the benchmark JAR and G5 `sample` path from the RGB16 reproduction steps above. The following JDK source-file launcher scans plugins before recording, enables events with a zero-duration threshold and filters on the canonical path. Run it once against each version with the same input and JDK.

```bash
cat > target/probe21/CountCr3Reads.java <<'JAVA'
import java.nio.file.Path;
import java.time.Duration;
import javax.imageio.ImageIO;
import jdk.jfr.Recording;
import jdk.jfr.consumer.RecordingFile;

class CountCr3Reads {
    public static void main(String[] args) throws Exception {
        var input = Path.of(args[0]).toRealPath();
        var log = Path.of(args[1]);
        ImageIO.scanForPlugins();
        try (var recording = new Recording()) {
            recording.enable("jdk.FileRead").withoutStackTrace().withThreshold(Duration.ZERO);
            recording.start();
            var image = ImageIO.read(input.toFile());
            recording.stop();
            if (image == null) throw new IllegalStateException("No ImageIO reader for " + input);
            recording.dump(log);
        }
        long calls = 0, bytes = 0;
        try (var events = new RecordingFile(log)) {
            while (events.hasMoreEvents()) {
                var event = events.readEvent();
                if (event.getEventType().getName().equals("jdk.FileRead") && input.toString().equals(event.getString("path"))) {
                    calls++;
                    bytes += event.getLong("bytesRead");
                }
            }
        }
        System.out.printf("%d file reads, %d bytes%n", calls, bytes);
    }
}
JAVA
"$java_bin" -XX:ActiveProcessorCount=4 -cp "$jar" target/probe21/CountCr3Reads.java \
    "$sample" target/probe21/reads.jfr
probe 768m -XX:+UseSerialGC "$sample" --mode default --warmup 0 --iterations 1 --checksum
```

For the other two captures use `research/g5xm2-detail-iso1600-ss0p4s-ff1p6-iq3-20260511-201012-02.cr3` and `eosr-iso-low.cr3`, both relative to `canon-cr3-imageio/src/test/resources/samples`. The checksum probe reports `checksum_kind=full-u16le-or-u8`, dimensions and bit depth alongside the hash.
