# RGB16 Bayer-pair interpolation

The RGB16 developer uses the repeating chroma and green pair for interior Bayer
rows. A complete interior pair uses two horizontal and two vertical neighbors,
so the interpolation uses fixed weights of one half and one quarter. Edge
pixels and incomplete pairs use the existing neighbor counts. The sample
normalization, floating-point addition order, matrix, output quantization and
row storage follow the preceding implementation. The implementation uses the
project's existing bilinear model and owned test captures. [RGB16 developer](../../canon-cr3-processing/src/main/java/com/photographer/focusstack/cr3/processing/Rgb16Developer.java)

## Full ImageIO imports

Each measured iteration opens an original CR3, develops full sRGB RGB16
through the ImageIO reader and closes its input. Measurements use Java
21.0.13, Serial GC, a 24 MiB initial and 768 MiB maximum heap, an AMD EPYC
9V74 host running Linux 6.18.57 x86-64 and four available CPUs. Each number
aggregates three independent JVM forks with alternating baseline/candidate
order, six warmup and eight measured imports per fork. Wall time, process CPU
time and allocated bytes use the median of the fork medians. RSS uses the
median of the process-lifetime high-water marks. The file cache and JVM are
warm.

| PowerShot G5 X Mark II RAW | 312.55 → 270.21 | −13.5% | 915 → 860 | 116.751 → 116.751 | 177.12 → 181.84 |
| EOS R RAW | 510.03 → 492.85 | −3.4% | 1480 → 1465 | 175.335 → 175.335 | 230.56 → 233.28 |
| PowerShot G5 X Mark II C-RAW | 252.56 → 254.18 | +0.6% | 765 → 720 | 118.157 → 118.157 | 183.98 → 186.57 |

The improvement in wall time was consistent across all G5 X Mark II RAW
forks. EOS R RAW and G5 X Mark II C-RAW wall times varied across forks.
The measured Java allocation was stable at the reported precision.

The single-CPU check used three forks per variant, four warmup imports and
five measured imports. Process CPU medians were 980 → 930 ms for G5 X Mark II
RAW, 1310 → 1330 ms for EOS R RAW and 850 → 790 ms for G5 X Mark II C-RAW.
Wall times varied substantially between single-CPU forks. The reproduction
command can repeat that check with one CPU in the affinity mask,
`-XX:ActiveProcessorCount=1`, `--warmup 4` and `--iterations 5`.

## Output comparisons

Both variants returned three 16-bit bands with matching dimensions and FNV-1a
over every output sample. Under a 144 MiB heap with EXIF orientation 6, both
variants completed the G5 X Mark II RAW read in automatic compact mode and
printed one compact-mode diagnostic.

| Original | RGB16 sRGB | RGB16 linear |
|---|---|---|
| PowerShot G5 X Mark II RAW | `482d0cb8385a95c5` | `4f883ba39badfbce` |
| EOS R RAW | `ba1e15e786312378` | `56c11a407c80c198` |
| PowerShot G5 X Mark II C-RAW | `5c286fbe36253461` | `8fb1786bb03ae7cc` |
| PowerShot G5 X Mark II RAW, orientation 6, 144 MiB heap | `52687e198ee9b749` | |

A separate comparison against the preceding developer checked each band of
103,680 synthetic outputs. It covered all four Bayer patterns, image
dimensions from 1–9 columns and 1–8 rows, crop origins spanning those
dimensions, orientations 1–8 and both transfer modes. It used unsigned
16-bit random samples from seed 18811, per-channel black levels, gains
and mixed positive and negative matrix coefficients. The processing reactor
passed with the optional vector unit test skipped and the packaged
integration test enabled.

## Reproduce

The comparison used the 0.1.8 CR3 libraries from Maven Central and a
classpath override for the single modified class. The baseline source and
probe are from commit `271db071539de2a0a2e4f5cdbeaeb432af65fba1`. The
baseline and released developer class have the same disassembled bytecode.
The measured classes and probe were compiled with `javac 25.0.5.1`. Compile
both `Rgb16Developer` variants and the probe with the same JDK and
`--release 21`. Set `candidate` to the revision containing the Bayer-pair
change. Run from the checkout root with a Java 21 runtime and a compiler
that supports Java 21.

```bash
run=$(mktemp -d)
mkdir -p "$run"/{lib,baseline,changed,probe,logs}
baseline=271db071539de2a0a2e4f5cdbeaeb432af65fba1
candidate=$(git rev-parse HEAD)
class=canon-cr3-processing/src/main/java/com/photographer/focusstack/cr3/processing/Rgb16Developer.java
probe=canon-cr3-benchmark/src/main/java/com/photographer/focusstack/cr3/benchmark/Cr3ImportProbe.java
central=https://repo.maven.apache.org/maven2

for module in codec container core imageio metadata processing; do
    curl -fLsS "$central/io/github/carstenartur/cr3-$module/0.1.8/cr3-$module-0.1.8.jar" \
        -o "$run/lib/cr3-$module.jar"
done
curl -fLsS "$central/org/slf4j/slf4j-api/2.0.20/slf4j-api-2.0.20.jar" -o "$run/lib/slf4j-api.jar"
git show "$baseline:$probe" > "$run/probe/Cr3ImportProbe.java"
javac --release 21 -cp "$run/lib/*" -d "$run/probe" "$run/probe/Cr3ImportProbe.java"
for variant in baseline changed; do
    revision=$baseline
    if [ "$variant" = changed ]; then revision=$candidate; fi
    git show "$revision:$class" > "$run/$variant/Rgb16Developer.java"
    javac --release 21 -cp "$run/lib/*" -d "$run/$variant" "$run/$variant/Rgb16Developer.java"
done

samples=canon-cr3-imageio/src/test/resources/samples
for sample in sample.cr3 eosr-iso-low.cr3 research/g5xm2-detail-iso1600-ss0p4s-ff1p6-iq3-20260511-201012-02.cr3; do
    for fork in 1 2 3; do
        order='baseline changed'
        if [ "$fork" = 2 ]; then order='changed baseline'; fi
        for variant in $order; do
            taskset -c 4-7 java -Xms24m -Xmx768m -XX:+UseSerialGC -XX:ActiveProcessorCount=4 \
                -cp "$run/$variant:$run/probe:$run/lib/*" \
                com.photographer.focusstack.cr3.benchmark.Cr3ImportProbe \
                --input "$samples/$sample" --mode rgb16 --warmup 6 --iterations 8 --gc-between \
                > "$run/logs/${sample##*/}.$fork.$variant.jsonl"
        done
    done
done
```

Use `--mode rgb16 --checksum` or `--mode rgb16linear --checksum` to
compare full image fingerprints in fresh processes. For the compact
comparison also use `-Xmx144m` and `--orientation 6`. Adjust CPU affinity to
suit the measurement host.
