# CR3 / CRX Clean-room Research

This is the maintained process entry for CRX semantic research. Read [Current state](current-state.md) before proposing an experiment.

## Present decision

The fixed lossless panel and registered public sources are insufficient to authorize a D14 entropy candidate.

D13 established that the panel contains 88 lossless single-subband records with stable topology and contiguous payloads, but it does not expose a deeper parent, LL/HL/LH/HH identity, causal `Sd` source or `Kd` lifecycle. Repeating current-symbol K rules, neighbor searches, predictor permutations or combined reset sweeps would fit the same saturated evidence rather than add knowledge.

Research may resume only when at least one genuinely new input exists:

- a legally usable multi-subband CRX corpus with independently established subband geometry and ordering;
- a permissible public primary source that fully specifies `Sd`, `Kd`, initialization, rounding, clamps and boundaries;
- first-party structural observations that identify causal context without selecting a rule by image quality.

The durable status is recorded in [Current state](current-state.md), [Open hypotheses](open-hypotheses.md) and [Results](reports/index.md).

## Mandatory clean-room boundary

All semantic CRX work follows the [clean-room engineering record](../cleanroom/README.md).

Researchers must not derive implementation behavior from third-party decoder source code. Permissible inputs, their registration and their allowed role are controlled by the clean-room source registry and contributor attestation process.

Black-box reference tools may produce output evidence, but their source code is not an implementation specification. Record tool version, command, input hash and output hash.

## Before an experiment

A research proposal must state:

1. **Novel evidence** — what new source, fixture or observation is unavailable in the current D13 panel?
2. **One hypothesis** — one causal statement that could be rejected.
3. **Fixed inputs** — exact fixture/manifest set selected before execution.
4. **Changed variable** — one implementation or observation boundary, not a broad combinatorial sweep.
5. **Primary metrics** — quantitative decision metrics chosen before seeing results.
6. **Physical guard metrics** — optical-black, completion, saturation, boundary or camera-family gates relevant to the hypothesis.
7. **Expected runtime and output** — local command, resource bound and durable artifact paths.
8. **Promotion rule** — explicit supported/rejected/partial criteria and what production code, if any, would become eligible for a later change.

If novelty cannot be explained, do not run the experiment.

## Evidence hierarchy

Use the strongest available evidence:

1. manifest-bound `RAW_LINEAR` TIFF references;
2. structural/container facts and independently known geometry;
3. physical sensor falsifiers, especially optical-black regions and completion;
4. rendered-preview metrics only as a secondary or tertiary sanity signal;
5. visual inspection for debugging, never as the sole promotion gate.

The shared `canon-cr3-reference-testkit` provides canonical reference loading, geometry/alignment validation, MAE/RMSE/Pearson, optical-black and boundary metrics, difference rendering and deterministic evidence writers. Do not reimplement equivalent local loops in each experiment.

## Fixed reference pipeline

The reference trust boundary is documented in [Reference export pipeline](../reference-pipeline.md).

Reference sidecars are:

- reproducibly generated by an independent black-box toolchain;
- classified as `RAW_LINEAR` or `PREVIEW_RENDERED`;
- hash-locked and geometry-checked through the manifest;
- resolved consistently by the shared testkit.

A missing or mismatched sidecar is not silently replaced with an embedded preview.

## Fixture acquisition

New captures are justified by the decision they enable, not by corpus size.

For each capture set:

- hold all non-experimental variables fixed;
- record camera model, firmware, connection/capture mode and settings;
- use deterministic names and manifest rows;
- record checksum and provenance;
- acquire paired or burst samples in one controlled session when testing stability or codec-mode differences;
- avoid registration/motion ambiguity for pixel-level comparisons;
- capture dark/flat/control frames only with documented physical setup;
- commit redistributable fixtures when practical or bind private fixtures through deterministic manifests and protected backup.

A proposed third camera, new scene class or large spatial corpus must explain why the existing two-camera/fixed-panel evidence cannot decide the question.

## Implementation scope

Initial work belongs in tests, `canon-cr3-research` or the reference testkit. Production modules remain unchanged until the research result passes its predeclared gate.

Research code may inspect internal codec stages, but production modules must not acquire runtime dependencies on:

- `canon-cr3-research`;
- `canon-cr3-reference-testkit`;
- benchmark modules;
- private reference files.

## Required outputs

Every completed experiment produces:

- machine-readable metrics (`.tsv`, `.csv` or `.json`);
- a deterministic human-readable report;
- exact command and source revision;
- fixture/manifest identifiers and hashes;
- implementation variant identifier;
- verdict and next step;
- updated [Current state](current-state.md), [Open hypotheses](open-hypotheses.md) and [Results index](reports/index.md) when the durable state changes.

Stdout-only conclusions are not durable evidence.

## Verify and update modes

Evidence generators must distinguish:

- **verify** — recompute/check and fail on missing or stale committed evidence without overwriting it;
- **update** — intentionally regenerate evidence after review of fixed inputs and expected changes.

CI uses verify mode. It never commits generated scientific output automatically.

## Production promotion

A semantic production change requires all of the following:

- hypothesis status `SUPPORTED` under its predeclared gate;
- durable result indexed under `docs/cr3-results/` or its migrated generated-report location;
- quantitative improvement on the primary metric;
- no prohibited camera-family, optical-black, completion, saturation or boundary regression;
- clean-room source and contributor records;
- regression tests using the shared metrics/contracts;
- a separate focused production PR.

`PARTIAL` is not sufficient for production promotion unless a separately scoped change has its own supported evidence.

## Do not repeat without new evidence

The current record already rejects or saturates:

- pure N/W/NW predictor swaps and broad predictor-family sweeps;
- tile/plane state continuation and general per-plane predictor splits;
- conventional zig-zag sign mapping;
- universal/current-symbol logarithmic K brackets;
- broad alignment and CFA rediscovery;
- transition-frequency fishing;
- combined `Sd`/`Kd`/reset searches on the same lossless single-subband panel;
- new blind C-RAW sweeps without lossy ground truth.

Use [Results](reports/index.md) to avoid reopening rejected directions.
