# Photographer 0.1.5 release candidate

Status: prepared for review, not published. Repository visibility stays private.
Prepared 2026-10-31 from `41d0460c76957717f67961c9d42328c50456ea7b`; development version remains `0.1.5-SNAPSHOT`.

## Changes since v0.1.4

- Split the clean-room Canon CR3 implementation into container, metadata, codec and processing modules with explicit dependency boundaries.
- Add a reference testkit and isolated external Maven-consumer verification for packaged CR3 artifacts.
- Document stable and experimental CR3 API surfaces; separate local product verification, research integration and benchmarking.
- Prepare supported CR3 modules for controlled Maven Central bundle validation without making publication or compatibility claims in advance.
- Refresh the application dependency stack and repair frontend/Java verification.

See [v0.1.4...candidate](https://github.com/carstenartur/Photographer/compare/v0.1.4...41d0460c76957717f67961c9d42328c50456ea7b),
[CR3 API boundaries](../cr3-api-boundaries.md) and [current decoder state](../cr3-current-state.md).
The modularization does not establish full RAW-decoder correctness or stable APIs for experimental research code.

## Candidate evidence and remaining qualification

The source commit has successful [product CI](https://github.com/carstenartur/Photographer/actions/runs/39127513159)
and [packaged consumer verification](https://github.com/carstenartur/Photographer/actions/runs/39127513090).
Those runs qualify the source commit, not this preparation commit; exact-head PR checks remain required.

Keep Maven as the build authority. Run the existing product, frontend, packaged-consumer and research gates
listed in the [candidate checklist](../release-checklist-0.1.5.md).
Then run existing **Release Workflow** (`deploy-release.yml`) from `main` with `dry_run=true`,
`skip_tests=false`, `next_version_increment=patch`, and `next_development_version=0.1.6-SNAPSHOT`.
The workflow checks out `main` regardless of the selector: merge the reviewed preparation before running it.

The existing workflow owns the stable POM transition, `v0.1.5` tag and next snapshot.
A real publication is a separate decision; this preparation leaves release tags, release dates and distribution settings unchanged.

## Distribution boundaries

After the successful application release and snapshot handoff, the release workflow invokes
Maven to sign and publish the six public CR3 libraries from the same verified tag.
Confirm Maven Central availability by resolving the released version in a clean consumer
build as described in the [CR3 publication runbook](../cr3-maven-central.md).
Repository visibility and historical-media/publication audits remain governed by [public-release.md](../public-release.md).
